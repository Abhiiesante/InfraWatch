## Overview

In V0, when an Inspector completes an inspection, the background worker generates a rigid, tabular PDF report using Puppeteer. While functional, enterprise clients often require narrative summaries for compliance audits (e.g., "Summarize the state of the cooling towers over the last 30 days and highlight any recurring safety violations").

In V1.1, we will integrate Large Language Models (LLMs) to automatically generate executive summaries and narrative reports from structured inspection data.

---

## Data Structuring (V0 Preparation)

LLMs suffer from hallucinations if they are not grounded in absolute factual data (RAG - Retrieval Augmented Generation).

**How V0 prepares for this:**
We strictly enforce typed fields in our database. An `Incident` doesn't just have a free-text `description`; it has a `status`, a `priority`, a `category`, and timestamps. 

When we prompt the LLM to write a report, we will pass it the exact JSON payload of these structured fields. The prompt will restrict the LLM to ONLY use the provided JSON to generate the narrative, significantly reducing hallucinations.

---

## LLM Integration Strategy

We will not build our own LLMs from scratch. We will use a managed service (like AWS Bedrock or OpenAI) accessed via an internal abstraction layer so we can easily swap providers if pricing or compliance requirements change.

**Workflow:**
1. Manager requests a "Weekly Narrative Summary" from the Dashboard.
2. The Node.js API queries the database for all incidents and inspections over the last 7 days for that tenant.
3. The API formats the raw database rows into a condensed JSON string.
4. A prompt is constructed: *"You are an industrial safety inspector. Based strictly on the following JSON data, write a 3-paragraph executive summary highlighting any P1 incidents and recurring equipment failures."*
5. The API calls the LLM provider.
6. The resulting text is embedded into the final PDF generated by the Puppeteer background worker.
