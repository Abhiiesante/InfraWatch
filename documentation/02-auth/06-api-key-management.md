## Overview

In V1.1, InfraWatch will support **Service-to-Service integrations** via API Keys. This allows tenants to write custom scripts or connect external tools (like PowerBI, custom ERPs, or IoT gateways) to the InfraWatch API without requiring a human to log in and maintain a JWT session.

---

## API Key Generation

Keys are generated by users with the `ADMIN` role. 

### Format

API Keys follow a standardized format to allow for fast identification and regex-based secret scanning (e.g., in GitHub to prevent accidental commits).

Format: `iw_{env}_{tenant_id}_{32_random_bytes_base62}`
Example: `iw_prd_t1_8f7K2pM9vQ4xL1zN6wE3cR0bY5hA2jD`

- `iw`: InfraWatch prefix
- `prd`: Environment (`prd`, `stg`, `dev`)
- `t1`: Tenant ID 1
- `Random Payload`: High-entropy secret

## Storage & Verification

To prevent database compromise from leaking API keys, **we do not store plaintext API keys**. 

1. **Generation:** When a key is created, the plaintext is shown to the user **exactly once**.
2. **Storage:** We generate a SHA-256 hash of the key and store the hash in the database.
3. **Verification:** When a request arrives, we hash the provided key and compare it to the database hash.

```typescript
// Conceptual generation
import crypto from 'crypto';

function generateApiKey(tenantId: number, env: string = 'prd') {
  const random = crypto.randomBytes(24).toString('base64url');
  const plaintextKey = `iw_${env}_t${tenantId}_${random}`;
  
  const hashedKey = crypto.createHash('sha256').update(plaintextKey).digest('hex');
  
  return { plaintextKey, hashedKey };
}
```

## Authentication Middleware

API Keys are passed in the HTTP headers. We use the standard `Authorization` header, but with the `ApiKey` scheme instead of `Bearer`.

`Authorization: ApiKey iw_prd_t1_8f7K2pM9vQ4x...`

```typescript
// Conceptual ApiKey Middleware
export const apiKeyMiddleware = async (req: Request, res: Response, next: NextFunction) => {
  const authHeader = req.headers.authorization;

  if (authHeader && authHeader.startsWith('ApiKey ')) {
    const key = authHeader.split(' ')[1];
    const keyHash = crypto.createHash('sha256').update(key).digest('hex');

    const apiKeyRecord = await prisma.apiKey.findUnique({
      where: { keyHash },
      include: { tenant: true }
    });

    if (!apiKeyRecord || !apiKeyRecord.isActive || apiKeyRecord.expiresAt < new Date()) {
      return next(new AppError('UNAUTHORIZED', 'Invalid or expired API Key', 401));
    }

    // Attach to request, simulating a system user
    req.user = {
      sub: 0, // System/API User
      tenantId: apiKeyRecord.tenantId,
      role: 'MANAGER', // API keys default to Manager permissions
      email: `api-key-${apiKeyRecord.id}@system.local`
    };
    
    return next();
  }
  
  // Fall through to JWT validation if no ApiKey header
  next();
};
```

## Database Schema

```sql
CREATE TABLE "api_keys" (
    "id"            SERIAL       PRIMARY KEY,
    "tenant_id"     INTEGER      NOT NULL REFERENCES "organizations"("id") ON DELETE CASCADE,
    "created_by_id" INTEGER      NOT NULL REFERENCES "users"("id"),
    "name"          VARCHAR(100) NOT NULL, -- e.g., "PowerBI Integration"
    "key_hash"      VARCHAR(64)  NOT NULL UNIQUE,
    "prefix"        VARCHAR(20)  NOT NULL, -- e.g., "iw_prd_t1_8f7K..." (for UI identification)
    "is_active"     BOOLEAN      NOT NULL DEFAULT true,
    "last_used_at"  TIMESTAMPTZ,
    "expires_at"    TIMESTAMPTZ,
    "created_at"    TIMESTAMPTZ  NOT NULL DEFAULT NOW()
);
```
